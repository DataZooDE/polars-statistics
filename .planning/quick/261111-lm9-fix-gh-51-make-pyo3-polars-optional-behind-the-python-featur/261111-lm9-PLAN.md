<objective>
Fix GitHub issue #51: Rust crates that depend on polars-statistics with
`default-features = false` still compile pyo3 + pyo3-ffi, because `pyo3-polars`
is a non-optional dependency and it switches on polars' own `python` feature.

Make `pyo3-polars` optional behind the existing `python` feature, cfg-gate every
`#[polars_expr]` `pl_*` plugin shim plus the shim-only helpers (output-dtype
functions and their imports) so the no-default rlib build is warning-free, add a
no-default-features clippy gate (plus a pyo3-absence guard) to CI, and correct the
Rust dependency instructions in README.md, docs/index.md and the src/lib.rs module
doc (the crate is not on crates.io — use a git dependency pinned to a release tag).

Purpose: the rlib path is advertised as "no pyo3 linkage"; today that is false.
Output: optional pyo3-polars, gated shims, a CI gate that keeps it that way,
accurate install instructions, and a CHANGELOG entry. No version bump (release is
a separate step).
</objective>
