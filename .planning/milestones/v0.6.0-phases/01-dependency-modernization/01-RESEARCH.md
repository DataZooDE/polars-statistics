The primary work is: (1) edit two version strings in `Cargo.toml`, (2) run `cargo update -p anofox-statistics -p anofox-regression` to regenerate `Cargo.lock`, (3) handle any compilation errors from the changed API surface, and (4) verify correctness via the existing test suites plus one new pivot-fix test.

**`anofox-statistics` 0.4.1→0.4.2** is a pure bug fix with no public API changes — only the internal p-value computation changed (survival function replaces `1 - cdf`). The wrapper's imports and call sites compile unchanged.

After the bump, **existing OLS/WLS tests will automatically exercise the fixed solver**, but the existing test suite uses well-scaled designs where the pivot permutation was always an involution (trivial), which is why the bug went undetected. DEP-04 requires adding a test on a differently-scaled design to confirm the fix is active.

**Primary recommendation:** Bump version strings → `cargo update` → `cargo check --all-features` → run `cargo test --no-default-features --test rust_api` → add pivot-correctness test → run full pytest suite.

## Column-Pivot Fix Verification (DEP-04 Correctness Gate)

### The Bug [VERIFIED: anofox-regression-0.5.13/CHANGELOG.md:13-18]

```
Column-pivot unpermute bug — silent wrong coefficients (#26, upstream #114). col_piv_qr
factorises A·P = Q·R, so the back-substituted solution is in pivot order and must be mapped
back through the pivot permutation. Five solvers undid this incorrectly, scattering
coefficients into the wrong slots whenever the pivot permutation was not an involution —
i.e. whenever the design's columns are on different scales (very common).

OlsRegressor and WlsRegressor: ... 186/200 multi-scale fits returned scrambled
coefficients. Now 0/200.
BlsRegressor / NNLS: 196/200 fits were wrong on a randomised multi-scale sweep. Now 0/200.
```

### What "Differently-Scaled" Means

The pivot permutation is non-trivial (not an involution) when column norms differ significantly. A simple reproducible case: three features where `x1` has norm ~1, `x2` has norm ~100, `x3` has norm ~0.01. The QR pivot reorders columns as `[x2, x1, x3]`, which is a 3-cycle, not an involution. Pre-fix, the unpermuting step was wrong for 3-cycles.

### Test Design for DEP-04 Pivot Test

The new test in `tests/rust_api.rs` must use `ols_fit` (the expression entry point, not `OlsRegressor` directly) on a design with differently-scaled columns, and assert the returned coefficients match the known ground truth within tolerance. The anofox-regression 0.5.13 internal test `r_validation_ols_pivot.rs` provides the reference pattern [VERIFIED: anofox-regression-0.5.13/tests/r_validation_ols_pivot.rs:27-60].

A minimal self-contained test:
```rust
#[test]
fn ols_column_pivot_fix_differently_scaled() {
    // Design: y = 1 + 2*x1 + 3*x2, where x1 ~ 1e0, x2 ~ 1e2.
    // This forces a non-trivial QR column pivot (3-cycle). Pre-fix, OLS scrambled
    // coefficients. Post-fix (0.5.13), must return [intercept~1, coef1~2, coef2~3].
    let n = 20usize;
    let x1: Vec<f64> = (0..n).map(|i| i as f64 * 0.5).collect();          // ~0..10
    let x2: Vec<f64> = (0..n).map(|i| i as f64 * 50.0).collect();         // ~0..1000
    let y: Vec<f64> = x1.iter().zip(x2.iter())
        .map(|(&a, &b)| 1.0 + 2.0 * a + 3.0 * b)
        .collect();

    let inputs = vec![
        series_f64("y", &y),
        scalar_bool("with_intercept", true),
        scalar_str_null("solve_method"),
        series_f64("x1", &x1),
        series_f64("x2", &x2),
    ];
    let out = ols_fit(&inputs).expect("ols_fit pivot test failed");
    let st = out.struct_().unwrap();
    let intercept = st.field_by_name("intercept").unwrap().f64().unwrap().get(0).unwrap();
    let coefs = st.field_by_name("coefficients").unwrap().list().unwrap().get_as_series(0).unwrap();
    let c1 = coefs.f64().unwrap().get(0).unwrap();
    let c2 = coefs.f64().unwrap().get(1).unwrap();

    assert!((intercept - 1.0).abs() < 1e-6, "pivot test: intercept got {intercept}");
    assert!((c1 - 2.0).abs() < 1e-6, "pivot test: x1 coef got {c1}");
    assert!((c2 - 3.0).abs() < 1e-6, "pivot test: x2 coef got {c2}");
}
```

This pattern must also be replicated for `wls_fit` (WLS) and the BLS path to satisfy the success criterion for OLS/WLS/NNLS.

## Common Pitfalls

### Pitfall 1: `cargo update` Updates Too Many Crates
**What goes wrong:** Running `cargo update` without `-p` flags updates ALL dependencies, including `polars` 0.52, `pyo3` 0.26, etc., which may introduce unrelated breakage.
**Why it happens:** Default `cargo update` updates all deps within semver constraints.
**How to avoid:** Always use `cargo update -p anofox-statistics -p anofox-regression` to pin the scope.
**Warning signs:** Lock file diff shows more than 3–4 changed packages.

### Pitfall 2: Testing Against the Old Binary
**What goes wrong:** After the Rust bump, running `pytest tests/` without `maturin develop` first tests the OLD cdylib. All Python tests pass but against stale code.
**Why it happens:** The installed `.so` in the venv is from the previous `maturin develop`.
**How to avoid:** Always run `maturin develop` (or `maturin develop --release`) before `pytest`.

### Pitfall 3: Pivot Test Using Well-Scaled Data
**What goes wrong:** A new "pivot correctness test" that uses equal-scaled features (e.g., `x1 = 1..20`, `x2 = 1..20`) will produce an identity pivot and pass even with the buggy 0.5.4 solver. The test proves nothing.
**Why it happens:** Equal column norms cause an involutive pivot (swap order), not a 3-cycle.
**How to avoid:** Use features with column-norm ratios of ≥ 100:1 (e.g., one column in 1e2 range, one in 1e0 range). The exact y = intercept + coef1*x1 + coef2*x2 ground truth must be verifiable analytically.

### Pitfall 4: Running `clippy` Without `--all-targets`
**What goes wrong:** CI runs `cargo clippy --all-targets -- -D warnings`. Running only `cargo clippy` locally skips test targets and integration tests, giving false confidence.
**How to avoid:** Run `cargo clippy --all-targets -- -D warnings` locally, matching CI.

### Pitfall 5: `cargo check` Passes but `maturin develop` Fails
**What goes wrong:** `maturin develop` requires the `python` feature and goes through a different code path than `cargo check --no-default-features`. Feature-gated code in pymodels may fail during the full build.
**How to avoid:** Run `cargo check --features python` (or full `maturin develop`) before marking DEP-01/DEP-02 complete.
