    The three functions are `ols_column_pivot_fix_differently_scaled`,
    `wls_column_pivot_fix_differently_scaled`, and `bls_column_pivot_fix_differently_scaled`. Each uses
    the same differently-scaled design: `n = 20`, `x1 = i*0.5` (range 0..10), `x2 = i*50.0`
    (range 0..1000), so the column-norm ratio is ~100:1, forcing a non-trivial 3-cycle QR column pivot.
    Ground truth is `y = 1 + 2*x1 + 3*x2`, so each test asserts intercept~1.0, x1 coef~2.0, x2 coef~3.0
    within `1e-6`.

    Input vector ordering (positional `&[Series]`, per src/expressions/regression.rs signatures and
    01-PATTERNS "Shared Patterns"): OLS is `[y, with_intercept, solve_method(null), x1, x2]`; WLS is
    `[y, w, with_intercept, solve_method(null), x1, x2]` with unit weights `w = [1.0; 20]`; BLS is
    `[y, lower_bound(-10.0), upper_bound(10.0), with_intercept, x1, x2]`. Extract results with the struct
    pattern: `out.struct_()` -> `field_by_name("intercept").f64().get(0)` for the intercept and
    `field_by_name("coefficients").list().get_as_series(0)` then `.f64().get(0)` / `.get(1)` for the two coefs.

    Do NOT use well-scaled / equal-norm features (per RESEARCH Pitfall 3): equal column norms produce an
    involutive pivot that passes even with the buggy pre-0.5.13 solver, proving nothing. The ~100:1 ratio
    is load-bearing. No new `use` statements are needed — `ols_fit`/`wls_fit`/`bls_fit` and the helpers
    are already in scope.

    Compile the test target and run only the three new tests to confirm they pass (they must pass now
    that Plan 01 bumped the crates to 0.5.13; they would have failed against 0.5.4).
