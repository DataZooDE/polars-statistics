# Phase 10 — Errors & API Consistency — Plan 10-01

**Milestone:** v0.7.0 — Ergonomics, Adoption & Documentation
**Requirements:** ERR-01, ERR-02, API-01, API-02

## Goal

Make the model/test surface best-in-class to consume: errors that name the
model and the fix, actionable shape/degenerate-input validation, a single
consistent `add_intercept` path (with `with_intercept` kept back-compatible via
`FutureWarning`), and uniform sklearn-style `fit`/`predict`/`score` across the
regressor classes.

## Approach

### ERR-01 — Contextual "not fitted" errors

- New shared module `src/pymodels/errors.rs` with
  `not_fitted_err(model)` / `not_fitted_test_err(model)` producing
  `PyRuntimeError` with the message
  `"<Model> is not fitted — call \`.fit(X, y)\` first."`.
- Mechanically replace the ~298 generic
  `PyErr::new::<PyRuntimeError, _>("Model not fitted" / "Test not fitted")`
  sites across `src/pymodels/*.rs` with the named helper (per-file class name).
- Exception **type stays `RuntimeError`** so existing
  `pytest.raises(RuntimeError)` assertions still hold; only the message
  improves.

### ERR-02 — Shape / degenerate-input validation

- `errors::validate_xy(model, &x, &y)` checks, before the solver runs:
  empty input, `X`/`y` row mismatch, and fewer rows than columns
  (rank-deficient by construction). Raises `PyValueError` with an actionable,
  model-named message.
- Called at the top of every regressor `fit`. Isotonic (1-D x) gets an
  equivalent inline guard in its `score`.

### API-01 — `add_intercept` deprecation on classes

- `errors::resolve_intercept(py, add_intercept, with_intercept, default)`
  mirrors the Python `_resolve_intercept`: both given → `ValueError`; only
  `with_intercept` → `FutureWarning` + use it; only `add_intercept` → use it;
  neither → default.
- Every model constructor that exposed `with_intercept` now accepts both
  `add_intercept` (preferred) and `with_intercept` (deprecated, kept working),
  routed through the helper. Applies to `#[new]` constructors and the ALM/GLMM
  static factory constructors.
- `fit_intercept` classes (BayesianRidge, ARD, LARS) are **left as-is** — API-01
  scopes only `with_intercept`; unifying `fit_intercept` would be a separate
  breaking-ish rename, deferred.
- Fix the stale "removed in v0.6.0" wording in the Python expression helper →
  "a future release".

### API-02 — Uniform `fit`/`predict`/`score`

- Add `score()` to every continuous regressor returning **R²**
  (`fitted.score(&x, &y)` from the `FittedRegressor` trait).
- Add `score(x, y, threshold=0.5)` to the binary classifiers (Logistic,
  Probit, Cloglog) returning **mean accuracy**, matching sklearn's
  classifier convention. LogisticRegression already had accuracy `score`.
- `fit`/`predict` signatures already uniform (X 2-D, y 1-D); Isotonic keeps its
  natural 1-D `x` in both `predict` and `score`.

### Stubs

- Regenerate `_polars_statistics.pyi` via `scripts/gen_stubs.py` after the Rust
  changes; the Phase 8 drift guard + mypy must stay green.

## Quality gates

- `cargo fmt --all -- --check`, `cargo clippy --all-targets --all-features -D warnings`
- `maturin develop`, `gen_stubs.py`, stub drift guard, `pytest`, `ruff`, `mypy`
- New tests: ERR-01 named unfitted, ERR-02 shape/degenerate `ValueError`,
  API-01 `FutureWarning` + both-kwargs error (classes AND exprs), API-02 score
  correctness (regressor R², classifier accuracy).
