## Fixed Issues

### WR-03: `tests/rust_api.rs` cannot link in the project's default feature set — the new Rust-level regression tests never actually run in CI

**Files modified:** `.github/workflows/ci.yml`
**Commit:** `8fdc186`
**Applied fix:** Added a `Rust API tests (no-default-features)` step to the existing `lint` job,
right after the `Clippy` step, reusing the same toolchain setup (no maturin/numpy/pyo3 needed).
The step runs `cargo test --no-default-features --test rust_api`. Before touching CI, verified
locally that this exact invocation passes (`timeout 1800 cargo test --no-default-features --test
rust_api` → 18/18 passed, reconfirmed again after all three fixes were committed). Also confirmed
that building `tests/rust_api.rs` *with* default features still fails at the link step with
undefined `PyGILState_Ensure`/`PyErr_Fetch`/etc. symbols (pyo3's `extension-module` feature,
pulled in by the default `python` feature, deliberately omits linking against libpython). The
inline CI comment notes that `rust_api.rs` is currently the only Rust test target in the crate,
so no other target is affected by the same linking gap. The crate's feature defaults
(`default = ["python"]` in `Cargo.toml`) were left unchanged, per the fix scope.

### IN-01: Missing blank line before `__repr__` in two of the four PyModel files touched

**Files modified:** `src/pymodels/py_huber.rs`, `src/pymodels/py_ransac.rs`
**Commit:** `a31e790`
**Applied fix:** Added the missing blank line between the last getter's closing `}` and the
`/// Informative repr...` doc comment, matching the convention already used at the equivalent
spot in `py_ridge.rs`, `py_wls.rs`, and `py_ols.rs`. Note: the review's cited line numbers
(`py_huber.rs:195-196`, `py_ransac.rs:533-534`) had drifted from the current file state (the
file has grown since the review was written); the actual gap in `py_huber.rs` was at the
`intercept_conf_interval` getter / `__repr__` boundary (around line 373), not at `n_outliers`
(around line 195) as the stale line reference suggested. Verified by reading the full getter
list in both files before editing. `py_ransac.rs`'s gap was at the `inlier_fit()` getter /
`__repr__` boundary, matching the review's description.

### IN-02: `FIXTURE_SHA256_PREFIX` holds the full digest and is compared with exact equality, not a prefix check

**Files modified:** `tests/test_wilcoxon_mcnemar_parity.py`
**Commit:** `1c821c9`
**Applied fix:** Renamed `FIXTURE_SHA256_PREFIX` to `FIXTURE_SHA256` (both the definition and its
one usage in `test_hodges_lehmann_fixture_integrity`), since the constant holds the full 64-hex-char
SHA-256 digest and the test correctly uses `==` exact-equality — a true prefix check was not the
original intent, so renaming (rather than truncating + `.startswith()`) is the faithful fix.
