**`ps.augment` exposes `anofox-regression`'s `diagnostics::augment` (R `broom::augment`) as one row-aligned expression for all nine Augmentable models plus `OLS.augment`/`WLS.augment` PyModel methods, validated against R 4.6.1 on the mtcars/warpbreaks m1a fixture and cross-checked against the pre-existing piecewise OLS diagnostics.**

## Accomplishments

- `ps.augment(y, *x, model="ols"|"wls"|"logistic"|"probit"|"cloglog"|"poisson"|"negative_binomial"|"tweedie"|"gamma", weights=None, residual_type=None, add_intercept=True, theta=None, var_power=1.5, max_iter=100, tol=1e-8)`: a single combined, row-aligned Polars expression (`returns_scalar=False`, like the `*_predict` expressions) returning `fitted`/`residual`/`std_residual`/`stud_residual`/`leverage`/`cooks_d`/`dffits` per input row. The Python builder validates model/residual_type/weights/theta/var_power eagerly (`ValueError` before `.collect()`) and resolves the default residual type (response for ols/wls, deviance for GLMs) so the Rust layer never guesses.
- `src/expressions/regression.rs`: `AugmentKwargs`, `parse_residual_type`, `augment_output_dtype`, `augment_fit`/`pl_augment` — model dispatch for all nine models, each built with the GLM builders' `max_iterations`/`tolerance` (and `theta`/`var_power` where relevant). Rows with a non-finite `y`/`x` (or, for `wls`, a non-finite/negative weight) are excluded from the fit and scattered back as NaN; the remaining rows equal a fit without them (mirrors `shrinkage.rs`'s `eb_shrink_fit` pattern).
- `src/pymodels/augment.rs` (new): `pub(crate) fn augment_dict<M: Augmentable + ?Sized>` — the single shared helper every PyModel `.augment()` method delegates to. `OLS.augment(x, y, residual_type=None)` and `WLS.augment(x, y, weights=None, residual_type=None)` (WLS defaults to the fit's own weights) both wrap it.
- R validation (mtcars/warpbreaks m1a fixture, reused verbatim from 16.3-02): OLS/WLS rel 1e-8; binomial-logit (deviance + Pearson), Poisson (deviance + Pearson), Gamma, Negative Binomial (estimated and fixed theta) rel 1e-6; Tweedie(`var_power=2.0`) reproduces Gamma's Cook's distance and response residual (required an explicit `.link_power(0.0)` — see Decisions); Probit/Cloglog checked for finiteness, leverage summing to rank, and response residual identity (no R reference table exists for these in the fixture).

- NA alignment (null `y`, separately NaN `x`) verified for ols/wls/poisson: the masked row comes back all-NaN and every other row matches a fit with that row dropped entirely.
- `.over(group)` matches two independent per-subset fits row-for-row; `group_by(...).agg(...)` returns a list of structs per group.

## Post-plan fix

`ps.augment(..., model="tweedie")` previously hard-coded `.link_power(0.0)` (log
link) in its Tweedie dispatch arm, while `ps.tweedie(...)` and `Tweedie()`
(`link_power=None`) default to `TweedieRegressorBuilder`'s own canonical link
(`1 - var_power`). This meant augment's diagnostics described a different
model than the one the user fits with the same arguments. Fixed by adding a
`link_power: float | None = None` keyword to `ps.augment`
(`python/polars_statistics/exprs/regression.py`), plumbed through a new
`AugmentKwargs.link_power: Option<f64>` field (`src/expressions/regression.rs`)
to the Tweedie dispatch arm, which now calls `.link_power(lp)` only when an
explicit value is supplied — otherwise it leaves the builder's canonical-link
default untouched, matching `py_tweedie.rs`. The Python builder raises
`ValueError` if `link_power` is passed for any model other than `"tweedie"`.
The pre-existing Tweedie(var_power=2) vs Gamma Cook's-distance cross-check in
`tests/test_augment.py` now passes `link_power=0.0` explicitly (it relies on
the log link, not the default); a new test
(`test_tweedie_default_link_matches_ps_tweedie`) confirms the default
(`link_power=None`) fitted values match a `Tweedie(link_power=None)` fit with
the same `var_power`. No PyO3 class signatures changed, so the generated
`.pyi` stub required no changes (confirmed via `scripts/gen_stubs.py`, no
diff).
