# Phase 16.3 Plan 04: Empirical-Bayes Shrinkage (eb_shrink) Summary

**`ps.eb_shrink(estimate, std_error, method="dl", tau_squared=None)` exposes anofox-regression 0.5.17's DerSimonian-Laird random-effects shrinkage as a row-aligned Polars expression, matching `metafor::rma(method = "DL")`/`blup()` to 1e-10 on both the upstream YI/SEI fixture and the 13-trial `metafor::dat.bcg` reference.**

## Performance

- **Duration:** ~25 min
- **Tasks:** 2 completed
- **Files modified:** 7 (3 created, 4 modified)

## Accomplishments

- `ps.eb_shrink(estimate, std_error, method="dl", tau_squared=None)` returns one struct row per input row — `{shrunken, shrunken_se, weight, mu, mu_se, tau_squared, i_squared, q, n_groups}` — matching `metafor::rma(yi, sei = se, method = "DL")` / `blup()` to within `1e-10 * max(|b|, 1)` on the upstream crate's own 5-row YI/SEI fixture and the 13-trial `metafor::dat.bcg` reference.
- `method="none"` pools completely (`tau_squared` exactly `0.0`, every `shrunken == mu` bit-for-bit) and a fixed `tau_squared` override both reproduce metafor's fixed-effect and fixed-tau² variants; `i_squared` stays Higgins-Thompson `(Q - df) / Q` as the upstream crate documents (differs from metafor's own `I2` only when `tau_squared` is supplied directly — a documented upstream difference, not a bug).
- Rows with a null/non-finite `estimate` or a non-positive/non-finite `std_error` stay aligned with NaN `shrunken`/`shrunken_se`/`weight` and are excluded from `mu`/`tau_squared`/`n_groups`; fewer than two usable rows (a single row, every row unusable, or an empty frame) give all-NaN rows with `n_groups` 0, never an exception.
- `.over(family)` shrinks each family independently (verified equal to running each family separately); `group_by(family).agg(ps.eb_shrink(...))` returns a list of structs per family with the same values.
- `eb_shrink_fit` is reachable from a downstream Rust crate via the rlib path, smoke-tested in `tests/rust_api.rs::eb_shrink_fits`.
- Invalid `method` or a negative/non-finite `tau_squared` raise `ValueError` at expression-build time (before `collect()`); a fixed `tau_squared` that fails upstream's own validation, or a length mismatch between `estimate`/`std_error`, is a `ComputeError` at the Rust layer.

## Decisions Made

- `eb_shrink` produces one output row per input row (`returns_scalar=False`), unlike `posthoc.rs`'s pairwise tests (one-row `List[Struct]`, `returns_scalar=True`) — every shrunken value belongs to an input row, so `df.with_columns(ps.eb_shrink(...).alias("eb")).unnest("eb")` aligns directly with the data and `.over(family)` shrinks per family. This was the plan's recorded shape decision and it worked exactly as specified, including the `.over()`/`group_by` equivalence test.
- Length mismatch between `estimate`/`std_error` is checked explicitly before calling upstream `eb_shrink` and raised as `ComputeError` directly, per the plan's "lengths must match, else ComputeError" contract (distinct from the "any other Err → NaN rows" degradation path, which covers `EmptyInput`/`InsufficientData`). The upstream `DimensionMismatch` variant is also matched explicitly to `ComputeError` as a defensive arm, though the pre-check means it should never actually be reached.
- `ShrunkenGroup.estimate`/`.se` (input echoes) are not output — a COVERAGE opt-out recorded in the plan, since callers already have the input columns available.
