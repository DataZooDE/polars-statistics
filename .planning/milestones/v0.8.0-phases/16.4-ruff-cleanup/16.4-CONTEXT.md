## Implementation Decisions

### Baseline (2026-10-15, ruff 0.16.8)
460 findings: UP007 319, I001 36, UP006 33, B017 20, F541 20, UP045 12, F401 7, UP035 6, F841 4, B007 3. The largest file is python/polars_statistics/exprs/regression.py (233); others are spread across exprs/*.py, formula/*.py, examples/, docs/assets/gen_plots.py and tests/.

### Rules
- **Python 3.9 runtime safety.** `X | Y` / `list[...]` annotations in runtime modules require `from __future__ import annotations` at the top of the module. Before adding it, check for runtime annotation consumers: `typing.get_type_hints`, dataclasses/pydantic/attrs that resolve annotations, `inspect.signature(...).parameters[...].annotation` compared as objects (tests/test_type_stubs.py uses `inspect.signature`), and polars `register_plugin_function` (does not inspect annotations). Adding `from __future__` must not change any test outcome, and the stub drift test must stay green.
- **Generated stub** `python/polars_statistics/_polars_statistics.pyi` is owned by scripts/gen_stubs.py. Never hand-edit it. If ruff flags it, fix the generator so the regenerated stub is clean (the drift guard must stay green), or exclude the generated file in pyproject `[tool.ruff] extend-exclude` with a comment giving the reason. Prefer fixing the generator if it is cheap.
- **B017** (`pytest.raises(Exception)`): replace with the specific exception actually raised. Determine it by running the test or reading the code; for PyO3 errors it is usually ValueError/RuntimeError/`polars.exceptions.ComputeError`. Never weaken the test.
- **F841 / B007 / F401**: fix them properly. If an unused import in an `__init__.py` is a deliberate re-export, use `__all__` or a redundant alias rather than deleting it.
- **examples/** and **docs/assets/gen_plots.py** are in scope. Their behaviour must not change; run the examples if they are cheap to run.
- Rules that cannot be satisfied without a behaviour or public-API change are disabled per-file (`[tool.ruff.lint.per-file-ignores]`) with a comment giving the reason. Do not ignore rules globally.
- **`ruff format`**: only add `ruff format --check` to CI if the repo already passes it, or if formatting is applied in this phase as a separate, behaviour-neutral commit. Decide from `ruff format --check .` output (planner/executor discretion; do not reformat if that would produce a huge noisy diff unrelated to lint).
- **CI**: add `ruff check .` to the lint job in .github/workflows/ci.yml, pinned to a ruff version or using the project's dev dependency so CI and local agree.
- **Gates**: full pytest, stub drift guard, skill harness and `mkdocs build --strict` stay green. No Rust changes are expected; cargo gates are unaffected.
- Do not touch package or crate versions.
