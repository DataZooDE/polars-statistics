Per CONTEXT §Release flow step 6. Never dispatch with `publish_to=pypi`, never create a tag or release, never edit secrets or workflow files.

For "decline": write the single line `declined` to `target/release-gate/testpypi-decision.txt`, record the choice in the SUMMARY, and finish. Nothing is dispatched.

For "run-testpypi":
1. Run `timeout 120 git fetch origin` and set OM to the origin/main tip. If OM differs from the merge commit M recorded in 17-03-SUMMARY, report what landed in between; the dispatch builds OM.
2. Check whether TestPyPI already has the version: `curl -s -o /dev/null -w '%{http_code}' https://test.pypi.org/pypi/polars-statistics/0.8.0/json`. 404 is expected. If it returns 200, the upload step's `skip-existing` will skip; record that and smoke the existing files.
3. Dispatch with `gh workflow run publish.yml --ref main -f publish_to=testpypi`. Then find the run: `gh run list --workflow publish.yml --event workflow_dispatch --limit 3 --json databaseId,headSha,status,createdAt`, taking the newest run whose headSha is OM. Re-issue the list up to 5 times while it has not appeared yet. Call the run ID RID.
4. Wait for the run. This is the allowed exception to the no-polling rule: `timeout 570 gh run watch "$RID" --exit-status --interval 60`. Exit 124 means it is still running, so re-issue (at most 10 calls), then report. Then print the jobs table: `gh run view "$RID" --json jobs --jq '.jobs[] | "\(.name)\t\(.conclusion)"'`. Required: all 6 Build jobs succeed, and "Publish to PyPI" is `skipped`.
5. If any Build job failed: this is a release blocker. Diagnose with `gh run view "$RID" --log-failed | tail -200`, write `run RID build-failed`, and stop with a checkpoint for the user (a fix needs a new PR). Do not continue to 17-05.
6. If only "Publish to TestPyPI" failed (e.g. HTTP 403 on a stale token): diagnose from the failed log, write `run RID upload-failed`, and report. The builds are proven. Do not modify the secret or the workflow.
7. If it uploaded: confirm `https://test.pypi.org/pypi/polars-statistics/0.8.0/json` lists 6 files. Then smoke-test, writing `target/release-gate/testpypi-smoke.log` as `{ ...; echo "EXIT=$?"; } > LOG 2>&1` around these commands:
   - `uv venv --python 3.12 --seed target/release-gate/tp312`
   - `target/release-gate/tp312/bin/pip install --no-cache-dir polars numpy` (from PyPI)
   - `target/release-gate/tp312/bin/pip install --no-cache-dir --no-deps --index-url https://test.pypi.org/simple/ polars-statistics==0.8.0`. Only our package comes from TestPyPI, with no dependency resolution there, which blocks a dependency-confusion substitute.
   - `target/release-gate/tp312/bin/python scripts/release_smoke.py --expect 0.8.0`

   TestPyPI's index can lag a minute behind the upload. If pip reports no matching distribution, re-issue the install (at most 5 times). Write `run RID uploaded`.
8. Record in the SUMMARY: the choice, RID, the jobs table, OM, the upload outcome, the smoke result and the TestPyPI URL.
  </action>
