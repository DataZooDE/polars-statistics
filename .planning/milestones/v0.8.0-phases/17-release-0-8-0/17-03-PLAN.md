2. Merge:
   - For "merge-commit": `timeout 120 gh pr merge "$PR" --merge --match-head-commit "$HS"`.
   - For "squash": `timeout 120 gh pr merge "$PR" --squash --match-head-commit "$HS"`.
   - For "merged": do not merge. Confirm `gh pr view "$PR" --json state` reports MERGED. If it does not yet, re-issue the check up to 5 times, then return a checkpoint asking the user to finish the merge.
3. Set M from `gh pr view "$PR" --json mergeCommit --jq .mergeCommit.oid`. Run `timeout 120 git fetch origin` and confirm M is an ancestor of origin/main.
4. Merged-tree version check:
   - `rm -rf target/release-gate/main-tree && mkdir -p target/release-gate/main-tree`
   - `git archive -o target/release-gate/main-tree.tar "$M" && tar -xf target/release-gate/main-tree.tar -C target/release-gate/main-tree`
   - write M into `target/release-gate/main-tree.sha`
   - `python3 target/release-gate/main-tree/scripts/check_version_alignment.py --expect 0.8.0`. The script's default root is its own repository copy, so this checks the merged tree.
5. Plugin live on GitHub main: `gh api "repos/DataZooDE/polars-statistics/contents/.claude-plugin/marketplace.json?ref=$M" --jq .name` returns marketplace.json.
6. Local sync, non-destructive: `git merge --ff-only origin/main`. If that is refused (local main carries post-push planning commits, or the PR was squashed), run `git merge --no-edit origin/main`. Both sides carry identical changes, so this merge is expected to be clean. If it conflicts, run `git merge --abort` and report; never reset, rebase or force. Afterwards origin/main must be an ancestor of local main.
7. Main CI: `gh run list --workflow ci.yml --commit "$M" --json databaseId,status` lists at least one run. GitHub may take a moment to create it, so re-issue the list command up to 5 times. Do not wait for it to finish here; 17-05 waits before tagging. Also record the docs deploy run (`gh run list --workflow docs.yml --commit "$M"`); a docs deploy failure is reported but does not block PyPI.
8. Record in the SUMMARY: merge method, M, the main CI run ID and the docs run status.
  </action>
