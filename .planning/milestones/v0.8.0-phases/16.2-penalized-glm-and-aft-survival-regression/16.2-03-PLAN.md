Upstream (anofox-statistics 0.4.7 `src/nonparametric/wilcoxon.rs`, unchanged from 0.4.6 lines 36-75):
`MannWhitneyResult` / `WilcoxonResult { statistic, p_value, estimate: Option<f64>, conf_int: Option<ConfidenceInterval { lower, upper, conf_level }>, null_value }`.
`estimate` and `conf_int` are `Some` only when `conf_level` is `Some`. One-sided alternatives give an interval with an infinite bound —
keep +/-inf as Float64 infinities, never NaN. (0.4.7's `TestResult` conversion is Phase 16.3 scope — do not use it here.)

Current code (read in read_first): `mann_whitney_u_fit` / `wilcoxon_signed_rank_fit` (src/expressions/nonparametric.rs) read `inputs[5]`
conf_level and `inputs[6]` mu but return `generic_stats_output(statistic, p_value, name)` with `#[polars_expr(output_type_func=stats_output_dtype)]`.
The Python builders filter non-finite values first (`x.filter(x.is_finite())`; Wilcoxon filters pairs). 16.1 Plan 02 added rank-biserial
expressions to nonparametric.rs and an effect-size dtype to output_types.rs — leave them untouched.

Known breakage this change causes (fix in the tasks, do not revert the feature): 16.1 Plan 09's
`tests/test_wilcoxon_mcnemar_parity.py::...expression_schema` asserts exactly `["statistic", "p_value"]`; `tests/test_group_by_over.py`
`test_mann_whitney_u_group_by` / `test_wilcoxon_signed_rank_group_by` / `..._over` call `has_valid_numbers(result)` without conf_level, which
now sees NaN estimate / ci fields. RESEARCH Pitfall 1: a failing schema-lock test after this change is the expected signal — update the test,
not the feature.

Gates: clippy `-D warnings`, cargo fmt; modified Python files pass `uv run ruff check --select F,E9`.
