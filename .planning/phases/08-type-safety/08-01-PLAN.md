# Phase 8 — Type Safety — Plan 08-01

**Milestone:** v0.7.0 Ergonomics, Adoption & Documentation
**Requirements:** TYPE-01, TYPE-02, TYPE-03

## Goal

Ship a `py.typed` marker plus accurate `.pyi` type stubs so IDEs and type
checkers (mypy/pyright) resolve every Rust-bound model/test class, the Python
expression builders, and the formula helpers with correct constructor, method,
getter, and return-type signatures — and guard against stub rot in CI.

## Tasks

1. Add empty `python/polars_statistics/py.typed` marker (PEP 561).
2. Author `scripts/gen_stubs.py`: introspect the compiled
   `polars_statistics._polars_statistics` module at runtime (classes,
   `__text_signature__`, getters vs methods) and map return types by parsing
   the `#[pyclass]`/`fn ... -> PyResult<...>` signatures in `src/pymodels/*.rs`.
3. Generate `python/polars_statistics/_polars_statistics.pyi` from that script.
4. Confirm the Python expression builders (`exprs/*.py`) and formula helpers
   (`formula/*.py`) are fully annotated (params typed, `-> pl.Expr`).
5. Add `tests/test_type_stubs.py`: a drift guard asserting every runtime class
   and member appears in the stub, no stale stub classes exist, and every
   re-exported expression builder is typed and returns `pl.Expr`.
6. Wire a CI `type-check` job: run the drift test, verify `gen_stubs.py`
   reproduces the committed stub byte-for-byte, and run a mypy smoke on the
   public API.
7. Verify the built wheel ships `py.typed` and the `.pyi`.
