## Facts established at planning time (2026-10-15, ruff 0.16.8, scratch copy, nothing applied)

- Every module with annotation findings already has `from __future__ import annotations`: regression, categorical, correlation,
  distributional, forecast, modern, nonparametric, parametric, tost, formula/expander, parser, terms. The three package `__init__`
  files and `models/__init__.py` lack it but have only I001 findings. Ruff only reports UP007 / UP045 at a py39 target when the
  future import is present. So the CONTEXT rule "add the future import where needed" is already satisfied, and Task 1 re-checks it.
- Runtime annotation consumers: the repo has no `typing.get_type_hints`, pydantic or attrs. `@dataclass` appears only in
  formula/terms.py, whose field annotations change only `List[...]` to `list[...]`. Those annotations stay strings, and dataclasses
  only string-match ClassVar / InitVar. `register_plugin_function` does not read annotations. tests/test_type_stubs.py reads
  `inspect.signature` annotations only to check that they are non-empty and that `"Expr" in str(return_annotation)`, and string
  annotations satisfy both checks.
- `formula/terms.py` defines a runtime alias, `Term = Union[SimpleTerm, InteractionTerm, PolyTerm, TransformTerm]`. Ruff does not flag
  it at py39, and it must stay `Union`, because `ClassA | ClassB` raises TypeError on 3.9. Do not hand-convert it.
- Trial of `ruff check python --fix --unsafe-fixes` on a copy: 390 fixed, 0 remaining. Full pytest results were the same as baseline (3.12: 1805 passed,
  6 skipped; 3.9: 1802 passed, 9 skipped, run via `uv run --offline --isolated --no-project --python 3.9 --with polars --with numpy
  --with pytest`). The API fingerprint (715 entries) was identical, and the AST guard reported 20/20 modules equal. Ruff marks these fixes "unsafe"
  only because runtime annotation consumers could evaluate the new syntax on Python < 3.10, and the previous bullet rules that out.
- Accepted side effect (threat T-16.4-03): on Python 3.9, `typing.get_type_hints()` resolves for 60 of 204 public builders
  before the change and 11 after. Many builders already use `bool | None`, so they already fail. Nothing in the repo calls it. The locked CONTEXT rule chooses
  PEP 604 annotations under the future import. On 3.12, all 204 still resolve, and the fingerprint checks this.
- `I001` in `exprs/__init__.py` reorders separate `from polars_statistics.exprs.<sub> import (...)` statements, and in
  `__init__.py` / `models/__init__.py` it reorders names inside one statement. Ruff keeps each category comment on the line
  it was attached to. If two submodules exported the same name, a reorder could change which binding wins. The API
  fingerprint catches that, and the trial showed no difference.

## Helper contract: `.planning/phases/16.4-ruff-cleanup/16.4-behaviour-guard.py` (written in Task 1)

Standard library only, plus `polars_statistics` for the `api` subcommand. It must be ruff-clean under the repo config. Two subcommands:

1. `api OUT_JSON`. Import `polars_statistics`. The first stdout line must be `fingerprinted: <polars_statistics.__file__>`, so the
   caller can confirm which tree was measured. Modules: `polars_statistics`, `.exprs`, `.models`, `.formula` and `.results`,
   plus every submodule found by `pkgutil.iter_modules` over the `__path__` of `.exprs` and of `.formula`, sorted. For each
   module, record the key `"<module>.__all__"` with the sorted `__all__`, or null. For each name in `sorted(dir(module))` that is
   not a dunder, include the object if any of these hold: the name is in that module's `__all__`; the object is a module whose
   `__name__` starts with `polars_statistics`; or the object's `__module__` is a string starting with `polars_statistics`. A
   module entry is `["module", obj.__name__]`. Any other entry is an object with these keys:
   - `module`: `__module__`.
   - `qualname`: `__qualname__`, falling back to the type name.
   - `params`: for callables, the list `[name, kind.name, repr(default)]` per parameter from `inspect.signature`; null if
     there is no signature.
   - `hints_resolve`: for `inspect.isfunction` objects only, a bool saying whether `typing.get_type_hints(obj)` succeeds;
     otherwise null.

   Annotation text is excluded on purpose, because it changes by design. Write the JSON with `sort_keys=True, indent=1`, and
   print a second line `entries: N`.
2. `ast REF PATH...`. For each PATH, read the old source with `git show REF:PATH` (subprocess, check=True) and the new source
   from the working tree. Parse both and normalise them with an `ast.NodeTransformer` that does four things:
   - (a) It drops every `Import` / `ImportFrom` node.
   - (b) It sets every function and async-function return annotation and every argument annotation (positional, keyword-only,
     `*args`, `**kwargs`) to None.
   - (c) It replaces every `AnnAssign` annotation with one fixed placeholder constant, keeping target and value.
   - (d) It replaces every f-string (`JoinedStr`) whose parts are all constants with the equivalent plain string constant.

   Compare `ast.dump(tree, include_attributes=False)`. Print `AST-equal: K of N` and one `DIFFERS: <path>` line per mismatch.
   Exit 1 on any mismatch, or if a path does not exist at REF. Exit 2 if no PATH is given, so an empty file list can never pass
   by checking nothing.

Typical calls:
- `uv run python .planning/phases/16.4-ruff-cleanup/16.4-behaviour-guard.py api "$T/after.json"`
- `uv run python .planning/phases/16.4-ruff-cleanup/16.4-behaviour-guard.py ast "$(cat .planning/phases/16.4-ruff-cleanup/16.4-base-ref.txt)" <paths>`
