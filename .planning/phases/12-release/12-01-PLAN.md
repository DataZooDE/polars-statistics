# Phase 12: Release 0.7.0

## Goal

Ship polars-statistics 0.7.0 — carrying all Phase 8–11 work (type stubs, result
ergonomics, contextual errors + API consistency, docs) — to production PyPI via
the existing GitHub Actions OIDC pipeline, with version aligned across all
sources so the v0.6.0 stuck-release failure mode cannot recur.

## Tasks

1. **REL-05** — bump `0.6.0 → 0.7.0` in every version source and keep them aligned:
   - `Cargo.toml` `[package].version`
   - `pyproject.toml` `[project].version`
   - `python/polars_statistics/__init__.py` `__version__`
   - `Cargo.lock` (synced via cargo)
   - Finalize CHANGELOG `[0.7.0]` section (dated) + compare link.
2. Land the bump via PR (CI green) → merge to `main`.
3. **REL-06** — trigger the release: tag `v0.7.0` at the merged commit + create the
   GitHub release → fires `publish.yml` (Trusted Publishing, no tokens).
   **GATED on explicit user confirmation** (irreversible production PyPI upload).
4. Post-release smoke check: `pip install polars-statistics==0.7.0` installs and
   imports cleanly; `polars_statistics.__version__ == "0.7.0"`.

## Verification

- All four version sources report 0.7.0 (checked pre-commit).
- Publish workflow run concludes success; PyPI latest = 0.7.0.
- Smoke check passes.

## Notes

- The v0.6.0 release failed with `400 File already exists` because the bump had
  only reached `Cargo.lock`, so maturin built 0.5.0-named wheels. This phase
  verifies alignment of ALL sources before tagging (REL-05 success criterion 1).
- `publish.yml` now carries `skip-existing` on the prod step (added during the
  v0.6.0 recovery), so a re-run tolerates pre-existing files.
