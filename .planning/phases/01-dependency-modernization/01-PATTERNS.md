**New tests to add — concrete design from RESEARCH.md:**

Three standalone `#[test]` functions appended after the existing `linear_regression_fits` block.
The differently-scaled design forces a non-trivial 3-cycle QR column pivot (column-norm ratio ≥ 100:1),
which exposed the pre-0.5.13 coefficient-scrambling bug.

```rust
#[test]
fn ols_column_pivot_fix_differently_scaled() {
    // y = 1 + 2*x1 + 3*x2, x1 ~ 1e0 range, x2 ~ 1e2 range.
    // Non-trivial QR pivot (3-cycle). Pre-0.5.13 OLS scrambled coefficients.
    let n = 20usize;
    let x1: Vec<f64> = (0..n).map(|i| i as f64 * 0.5).collect();   // 0..10
    let x2: Vec<f64> = (0..n).map(|i| i as f64 * 50.0).collect();  // 0..1000
    let y: Vec<f64> = x1.iter().zip(x2.iter())
        .map(|(&a, &b)| 1.0 + 2.0 * a + 3.0 * b)
        .collect();

    let inputs = vec![
        series_f64("y", &y),
        scalar_bool("with_intercept", true),
        scalar_str_null("solve_method"),
        series_f64("x1", &x1),
        series_f64("x2", &x2),
    ];
    let out = ols_fit(&inputs).expect("ols_fit pivot test failed");
    let st = out.struct_().unwrap();
    let intercept = st.field_by_name("intercept").unwrap().f64().unwrap().get(0).unwrap();
    let coefs_inner = st.field_by_name("coefficients").unwrap().list().unwrap().get_as_series(0).unwrap();
    let c1 = coefs_inner.f64().unwrap().get(0).unwrap();
    let c2 = coefs_inner.f64().unwrap().get(1).unwrap();

    assert!((intercept - 1.0).abs() < 1e-6, "pivot OLS intercept: expected 1.0, got {intercept}");
    assert!((c1 - 2.0).abs() < 1e-6, "pivot OLS x1 coef: expected 2.0, got {c1}");
    assert!((c2 - 3.0).abs() < 1e-6, "pivot OLS x2 coef: expected 3.0, got {c2}");
}
```

## Shared Patterns

### Multi-feature `inputs` vec ordering for `ols_fit` / `wls_fit`

**Source:** `tests/rust_api.rs` lines 113–118 (OLS) and 152–158 (WLS)

The expression functions accept `&[Series]` positionally. For multi-feature designs the order is:

- `ols_fit`: `[y, with_intercept (bool scalar), solve_method (str scalar or null), x1, x2, ...]`
- `wls_fit`: `[y, w (weights), with_intercept, solve_method, x1, x2, ...]`
- `bls_fit`: `[y, lower_bound (f64 scalar), upper_bound (f64 scalar), with_intercept, x1, x2, ...]`

This ordering is defined by the expression function signatures in `src/expressions/regression.rs`
and must be followed exactly. The existing single-feature tests confirm the positions for indices 0–3;
additional features append at the end.

### Struct field extraction pattern

**Source:** `tests/rust_api.rs` lines 120–137

All `*_fit` results are `Struct` series. Extract fields with:
```rust
let st = out.struct_().unwrap();
let val = st.field_by_name("field_name").unwrap().f64().unwrap().get(0).unwrap();
// For list fields (coefficients):
let coefs_inner = st.field_by_name("coefficients").unwrap().list().unwrap().get_as_series(0).unwrap();
let c0 = coefs_inner.f64().unwrap().get(0).unwrap();
```
