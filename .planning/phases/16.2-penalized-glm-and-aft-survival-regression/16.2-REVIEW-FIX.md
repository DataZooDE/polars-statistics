### CR-01: `aft_predict_quantile`/`_median`/`_survival`/`_cdf` silently misinterpreted invalid event codes

**Files modified:** `src/expressions/aft.rs`, `tests/rust_api.rs`, `tests/test_aft.py`
**Commits:** `7039c7a` (fix), `9288d7a` (clippy follow-up)
**Applied fix:** Replaced `aft_predict_impl`'s permissive `event_bool`/`event_null_mask`
construction (which silently mapped any non-`1.0` numeric value, e.g. R's `2.0`, to `Some(false)`
— i.e. "censored") with validation that exactly mirrors `aft_inputs()`'s strict contract: a
non-Boolean event value other than `0.0`/`1.0` now returns the same all-NaN prediction struct
(`prediction_nan_output_with_prefix`) that `aft_fit`/`aft_summary_fit` return for the equivalent
input, instead of silently fitting on a misread value.

Added regressions:
- `tests/test_aft.py::TestAftEventCoding::test_predict_event_coding_invalid_gives_nan` — exercises
  all four `aft_predict_*` expressions with a corrupted (`2.0`) event code and asserts every
  prediction is `NaN`.
- `tests/rust_api.rs::glm_fits` — added an `assert_f64_all_nan` helper and an rlib-level assertion
  block (same `glm_fits` test that already exercises the AFT `*_fit` functions) calling all four
  `aft_predict_*_fit` functions with an invalid numeric event code and asserting an all-NaN
  `aft_prediction` field, matching the existing in-test pattern for AFT rlib coverage (no prior
  rlib assertion existed for invalid event coding on the fit side either, so this adds the first
  one, extended to all four predict variants as the fix explicitly requested).

A follow-up commit (`9288d7a`) was required after the initial fix failed
`cargo clippy --all-targets -- -D warnings` (`redundant_guards` on the `Some(v) if v == 0.0` /
`Some(v) if v == 1.0` match arms); fixed by matching the literal patterns directly
(`Some(0.0)` / `Some(1.0)`), per clippy's own suggestion. No logic change.

**Human verification note:** this is a logic-correctness fix (event-coding validation), not a
pure refactor. The rlib and Python regressions above both exercise the specific failure mode from
the review's reproduction (`event` corrupted from `1.0` to `2.0`), and both assert the documented
all-NaN contract rather than merely "doesn't panic," so confidence is high — but per the fixer's
verification-strategy guidance, logic fixes should still get a human skim of the diff.
