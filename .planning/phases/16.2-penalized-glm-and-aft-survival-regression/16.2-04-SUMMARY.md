# Phase 16.2 Plan 04: Penalized GLM Summary + Predict Expressions Summary

**`ps.penalized_glm_summary`/`ps.penalized_glm_predict` complete the penalized GLM expression family with R-validated confidence intervals (intercept inference read directly from upstream, never recomputed) and response/link-scale predictions, including a fix for a subtle NaN-offset-vs-link-clamp interaction found while testing.**

## Performance

- **Files modified:** 7

## Accomplishments

- `src/expressions/penalized_glm.rs`: new `inference_summary_output_dtype`/`inference_summary_output`/`inference_summary_nan_output` (7-field tidy summary: term, estimate, std_error, statistic, p_value, ci_lower, ci_upper) — separate from the shared 5-field `summary_output_dtype`, which stays untouched.
- `penalized_glm_summary_fit` fits with `compute_inference=true`; the intercept row's std_error/statistic/p_value/CI come straight from upstream's `GlmInferenceResult::intercept_std_error/_z_value/_p_value/_ci_lower/_ci_upper` — never recomputed locally (confirmed by a `grep -c "inverse_cdf|ContinuousCDF"` == 0 gate). Matches R standard errors for Poisson, Gamma, Negative Binomial, and quasipoisson (`estimate_dispersion=True`) including the intercept row, and equals the `PenalizedGLM` PyModel's inference getters exactly.
- `penalized_glm_predict_fit` refits per group/`.over()` partition with the same options as `penalized_glm_fit`, then predicts on every row at `type="response"` (inverse-link applied) or `type="link"` (linear predictor + offset only). `lower`/`upper` are always NaN — `FittedPenalizedGlm` has no interval-prediction method (already recorded as an OPT-OUT in this phase's `COVERAGE.md`).
- **Bug found and fixed during Task 2's own testing**: a null offset was expected to propagate to a NaN prediction via ordinary float arithmetic (`eta + NaN = NaN`, then `link_inverse(NaN)`), but `anofox_regression`'s `PoissonLink::link_inverse` clamps its result via `eta.exp().max(1e-14)` for numerical stability — and Rust's `f64::max` returns the *non-NaN* operand when one side is NaN, silently turning the intended NaN into the clamp floor `1e-14`. Fixed by computing an explicit `offset_null_mask` from the raw offset column and forcing those rows to NaN in the output unconditionally (not dependent on `null_policy` or the family's link behavior).
- `src/expressions/regression.rs`: `build_term_names`, `build_xy_with_null_policy`, `predict_output_dtype_with_prefix`, `prediction_output_with_prefix`, `prediction_nan_output_with_prefix` widened `fn` -> `pub(crate) fn` (visibility-only; verified by a literal diff gate before each task's commit) so `penalized_glm.rs` can reuse them without duplicating code.
- `python/polars_statistics/exprs/regression.py`: `penalized_glm_summary` (validates `vcov_type`/`conf_level` at build time), `penalized_glm_predict` (validates `type`/`null_policy` at build time), `penalized_glm_formula_summary`, `penalized_glm_formula_predict` — all following the existing builder/formula-wrapper patterns, exported from both `exprs/__init__.py` and the package `__init__.py`.
- `tests/rust_api.rs`: new smoke block for `penalized_glm_fit`/`penalized_glm_summary_fit`/`penalized_glm_predict_fit` with `PenalizedGlmKwargs`, including `Err` (no panic) assertions for an invalid family and for `estimate_dispersion` on a non-Poisson family.
- `tests/test_penalized_glm.py`: 31 new tests across `TestPenalizedGlmSummary` (13), `TestPenalizedGlmPredict` (10), and two new `TestPenalizedGlmFormula` tests, covering every behavior bullet in the plan.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] Fixed offset-null-row prediction silently returning a finite clamp floor instead of NaN**
- **Found during:** Task 2 (writing `test_predict_null_policy`)
- **Issue:** The plan's design (and my initial implementation) assumed a null offset would propagate to a NaN prediction via ordinary float arithmetic (`eta + NaN = NaN`, then the family's inverse-link applied to NaN). For the Poisson log link, `anofox_regression::core::PoissonLink::link_inverse` clamps its result for numerical stability via `eta.exp().max(1e-14)`; Rust's `f64::max` returns the *other* (non-NaN) operand when either side is NaN, so `NaN.max(1e-14)` silently evaluates to `1e-14` instead of `NaN`. A test asserting `math.isnan(...)` at an offset-null row failed with `1.0000e-14` instead.
- **Fix:** Compute an explicit `offset_null_mask: Vec<bool>` from the raw (non-scalar) offset column before any arithmetic, and force the output prediction to NaN at those rows unconditionally — independent of `null_policy` and not relying on any family's inverse-link NaN-propagation behavior.
- **Files modified:** `src/expressions/penalized_glm.rs`
- **Verification:** `tests/test_penalized_glm.py::TestPenalizedGlmPredict::test_predict_null_policy` passes under both `null_policy` values; full suite green afterward.
- **Committed in:** `87d67c8` (Task 2 commit)

---

**Total deviations:** 1 auto-fixed (1 Rule 1 bug)
**Impact on plan:** Necessary for correctness — without this fix, a null offset would silently produce a near-zero (not NaN) prediction for any family whose inverse-link clamps via `f64::max`/`f64::min`. No scope creep: the fix is confined to the one function this plan's Task 2 introduced.
