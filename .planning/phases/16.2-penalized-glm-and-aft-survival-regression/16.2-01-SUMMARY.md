## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - Blocking] `cargo update -p X --precise V` called twice (as literally specified) reproducibly moved unrelated transitive deps (windows-sys)**
- **Found during:** Task 1
- **Issue:** The plan's recipe runs `cargo update -p anofox-statistics --precise 0.4.7` then `cargo update -p anofox-regression --precise 0.5.22` as two separate invocations. Reproduced three times: the first invocation alone (which already resolves both crates, since Cargo.toml's caret floors make 0.5.22/0.4.7 the only compatible versions) produces a clean diff touching only the two anofox entries; a *second* `cargo update` call (even a semantic no-op re-affirming the same precise version) re-queries the crates.io index and can shift 6 unrelated `windows-sys` version selections elsewhere in the lockfile — a lockfile-hygiene violation of the plan's own "only the two anofox entries... may change" instruction it explicitly warns against ("if unrelated crates moved, restore the copy and repeat with `--precise`").
- **Fix:** Restored the saved pre-update `Cargo.lock` copy and ran a single `cargo update -p anofox-statistics -p anofox-regression` (no `--precise`, both packages in one call, one index query). Diff was clean (only the two anofox entries' version/checksum lines changed).
- **Files modified:** Cargo.lock (gitignored, not committed)
- **Verification:** `diff` against the saved pre-update copy showed exactly 4 diff hunks (version + checksum for each of the two crates), confirmed via `grep -A1 'name = "..."' Cargo.lock`
- **Committed in:** `549a173` (Task 1 commit; the lockfile itself is gitignored, but the Cargo.toml floor change and this behavior are recorded here)

**2. [Rule 3 - Blocking] Sequential-executor instructions direct committing to `main`, but the executor's default protected-branch guard reports `main` as protected**
- **Found during:** Task 1 (pre-commit)
- **Issue:** `gsd_run query git.base-branch --is-protected main` returns `true` by the executor's five-name fallback (`main|master|develop|trunk|release/.*`), which would HALT every commit in this plan. This project's `.planning/config.json` has `git.branching_strategy: "none"` (trunk-based) and every prior phase (1 through 16.1, confirmed via `git log`) committed directly to `main` — this is the project's established, intentional workflow, not an accidental drift onto a protected branch.
- **Fix:** Set `git.allow_default_branch_commits: true` in `.planning/config.json` via `gsd_run query config-set`, which the protected-branch guard's own documentation names as the sanctioned override for exactly this situation.
- **Files modified:** `.planning/config.json`
- **Verification:** `gsd_run query git.base-branch --is-protected main` returns `false` after the config change
- **Committed in:** `549a173` (Task 1 commit)

**3. [Rule 1 - Bug] Pre-existing stale "Expected output" values in `docs/examples/glm-models.md` discovered while re-running every snippet for the 0.5.19-0.5.21 refresh**
- **Found during:** Task 3
- **Issue:** Re-running every Python snippet in the file (as Task 3's action explicitly instructs) surfaced three issues that predate this bump and are independent of the 0.5.19-0.5.21 changes: (a) `print(f"N: {model['n']}")` raises `KeyError: 'n'` — the actual field is `n_observations`; (b) the basic Poisson/NegBin "AIC" values (11.82/5.65) did not match R's own `glm()`/`glm.nb()` AIC formula (independently verified against `scipy.stats.poisson.logpmf` — the correct value is 73.23/75.23); (c) the Tweedie `var_power=1.5` "AIC: 148.32" directly contradicted the Tweedie builder's own, already-existing docstring ("Model-level aic/bic are NaN unless var_power is one of 0, 1, 2, or 3").
- **Fix:** Corrected the field name and all three AIC values to the live, verified-correct output; rewrote the NegBin section's narrative since the corrected numbers show NegBin no longer "beats" Poisson on this near-Poisson toy dataset.
- **Files modified:** `docs/examples/glm-models.md`
- **Verification:** All three values independently cross-checked (field existence via a 2-row example; AIC via a from-scratch `scipy.stats.poisson.logpmf` computation; Tweedie NaN via the existing, unmodified docstring in `python/polars_statistics/exprs/regression.py`)
- **Committed in:** `63f3553` (Task 3 commit)
