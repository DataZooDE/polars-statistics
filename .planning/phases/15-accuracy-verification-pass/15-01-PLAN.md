The one proven path must do all of: (1) read a SKILL.md file; (2) extract every fenced code block whose info-string starts with `python` using a markdown fence parser (match the opening fence's language token, capture lines until the matching closing fence — do not regex across nested backticks); (3) for each block, decide runnable vs marked-non-runnable via a marker convention (see below); (4) execute each runnable block in a fresh namespace via Python `exec` inside THIS interpreter (the script is already launched under `uv run`, so the live package is importable — do not spawn per-block subprocesses); (5) collect per-block PASS / FAIL / SKIP with the failing traceback captured via `traceback.format_exc()`; (6) print a per-block report line and a summary, and `sys.exit(1)` if any block FAILs.

Marker convention for intentionally-non-runnable blocks (illustrative pseudo-snippets, output displays, literal `...` ellipses, external-file reads like `pl.read_csv("data.csv")`): a block is treated as SKIP only when its first content line is exactly the comment `# verify: skip -- <reason>` (reason required and non-empty). SKIP blocks are reported with their reason (visible, not silent) and do NOT count as failures. Any block lacking that marker is treated as runnable and MUST execute green. Emit a distinct FAIL for a block that errors AND for a SKIP marker with an empty reason, so a lazy blanket-skip cannot hide a broken example.

Shared setup across sequential blocks in a file (some blocks reference `df` defined in an earlier block): execute a file's runnable blocks in document order in ONE shared namespace so earlier imports/DataFrame definitions remain visible to later blocks — this matches how a reader copies down the page. Reset the namespace between files.

Ground the runtime-authoritative check: the script confirms the live package imports (`import polars_statistics`) at startup and fails fast with a clear message if it cannot, so a broken environment is never mistaken for green.
