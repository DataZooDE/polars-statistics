## Accomplishments

- `LinearAliasKwargs { alias_tolerance: f64 }` (default `anofox_regression::utils::LM_ALIAS_TOLERANCE = 1e-7`) threaded through `ols_fit_with`/`wls_fit_with`/`ols_summary_fit_with`/`wls_summary_fit_with` and their `pl_ols`/`pl_wls`/`pl_ols_summary`/`pl_wls_summary` plugin shims; the positional `ols_fit`/`wls_fit`/`ols_summary_fit`/`wls_summary_fit` signatures are unchanged and delegate with the default.
- `LinearAliasPredictKwargs { prefix, alias_tolerance }` + `linear_alias_predict_output_dtype` (delegates to the existing `predict_output_dtype_with_prefix`) for `ols_predict_fit_with`/`wls_predict_fit_with` and their `pl_ols_predict`/`pl_wls_predict` shims.
- `OLS(alias_tolerance=1e-7)` and `WLS(alias_tolerance=1e-7)` PyModel constructor kwargs, validated (finite, `>= 0`) in the Rust ctor with a `PyValueError`.
- Python builders `ols`, `wls`, `ols_summary`, `wls_summary`, `ols_predict`, `wls_predict` all accept `alias_tolerance: float = 1e-7`, validated via a new `_check_alias_tolerance` helper (mirrors the `ps.augment` validation style); every formula wrapper (`ols_formula`, `wls_formula`, `ols_formula_summary`, `ols_formula_predict`) forwards it.
- R validation against upstream issue #64 (`anofox-regression` 0.5.22's `tests/issue64_lm_aliasing.rs`): a tighter `alias_tolerance` (`1e-6`) aliases a column the default (`1e-7`) keeps at ratio `2e-7` (R reference intercept `2.023318557879104`, coefficients `1.490290680634032`/`-0.772169023108856`, SEs `0.0161213612630192`/`0.0396174535357292`, `rmse` `0.216257642550628`, `r_squared` `0.993640840379574`, `adj_r_squared` `0.993417711971839`, all `1e-9`); the default keeps it (R `30169.122`/`30166.860`/`-30167.632`, `rmse` `0.217068502408162`, `1e-4`/`1e-8`); a smaller tolerance (`1e-8`) keeps a column the default aliases at ratio `0.5e-7`.
- LARS exposes `adj_r_squared`, `mse`, `rmse` (filled since `anofox-regression` 0.5.21 #65): full LAR path matches R `summary(lm())` (`adj. r_squared` `0.993417711971839`, `rmse` `0.216257642550628`, `1e-9`); LassoLars (`alpha=0.05`) uses `df = active + intercept` (`rmse == sqrt(RSS / df_resid)`, `adj = 1 - (1-R²)(n-1)/df_resid`, `1e-12`); LAR without an intercept matches `OLS(add_intercept=False)`'s `rmse` (`1e-8`).
- `tests/rust_api.rs::alias_tolerance_fits`: rlib smoke test for the six `*_fit_with` variants on a near-collinear design, confirming the positional contracts and default behavior of `ols_fit`/`wls_fit` are unchanged.
