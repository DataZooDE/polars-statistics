## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] Missing `FittedRegressor` import in py_logistic_regression.rs**
- **Found during:** Task 2 build verification
- **Issue:** `fitted.inner().result()` requires the `FittedRegressor` trait in scope for `.result()` to resolve (private-field vs trait-method ambiguity); the file only imported `FittedLogistic`, `LogisticRegression`, `Penalty`. Build failed with `E0599: no method named 'result' found ... private field, not a method`.
- **Fix:** Added `FittedRegressor` to the `use anofox_regression::solvers::{...}` import list.
- **Files modified:** `src/pymodels/py_logistic_regression.rs`
- **Verification:** `cargo build --lib` clean; all `LogisticRegression` tests pass.
- **Committed in:** `0fc785a` (Task 2 commit)

**2. [Rule 1 - Bug] `test_to_dict_values_are_json_like` broken by OLS's new `intercept_conf_interval`**
- **Found during:** Task 3 full-suite verification
- **Issue:** `OLS().fit(x, y).to_dict()` now includes `intercept_conf_interval`, a `(float, float)` tuple (the 16.1 Huber convention mirrored onto OLS in this plan). The pre-existing assertion `isinstance(v, (int, float, bool, np.ndarray))` predates any tuple-valued field and rejected it.
- **Fix:** Widened the assertion to also accept a 2-tuple of `int`/`float` elements, with an explicit shape/content check rather than a blanket `isinstance(v, tuple)` pass-through.
- **Files modified:** `tests/test_ergonomics.py`
- **Verification:** `tests/test_type_stubs.py tests/test_ergonomics.py` (40/40) and the full suite (1603 passed) green.
- **Committed in:** `a448316` (Task 3 commit)
