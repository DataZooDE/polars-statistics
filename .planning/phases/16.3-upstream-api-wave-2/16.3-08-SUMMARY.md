# Phase 16.3 Plan 08: model_info rollout (UPST-09) Summary

**Added a `model_info` getter (`{"model_type": str, "family": str | None, "link": str}`) to all 30 PyModel classes whose upstream fitted type implements anofox-regression's `HasModelInfo`, via one shared `model_info_dict` helper.**

## Performance

- **Duration:** ~20 min
- **Tasks:** 3
- **Files modified:** 35 (33 Rust/stub/test files + 1 ergonomics test touch, across 3 commits)

## Accomplishments
- Shared `src/pymodels/model_info.rs::model_info_dict` helper builds the `{model_type, family, link}` dict from `anofox_regression::ModelInfo`, mirroring the `augment.rs`/`ergonomics.rs` shared-helper convention.
- `model_info` getter added to all 30 `HasModelInfo`-backed classes: OLS, WLS, Ridge, ElasticNet, RLS, BLS, PLS, Quantile, Isotonic, Huber, TheilSen, RANSAC, BayesianRidge, ARD, LARS, PassiveAggressive, PSpline, LmDynamic, ALM, Logistic, Probit, Cloglog, LogisticRegression, Poisson, NegativeBinomial, Tweedie, Gamma, GLMM, PenalizedGLM, AFT.
- Capture-at-fit for the three classes that still type-erase their fit: ElasticNet, RLS, BLS (each adds `model_info: Option<anofox_regression::ModelInfo>`, set from the concrete fitted value immediately before `Box::new(fitted)`, so it's correct on every refit). BLS reports `"nnls"` vs `"bls"` matching upstream's bound-based dispatch.
- `tests/test_model_info.py` (new, 39-row parametrized expected-info table sourced from anofox-regression 0.5.22's own `tests/model_info.rs`, plus unfitted-raises for all 30 classes, `to_dict()` presence, boxed-refit-keeps-own-type, and an exact-30-class coverage assertion against the compiled `_polars_statistics` module).
- Full suite green (1795 passed, 6 pre-existing skips), `cargo test --no-default-features --test rust_api` green (22/22), stub drift guard clean.

## Decisions Made
- Ridge uses the direct `fitted.model_info()` getter (like OLS), not the boxed-capture pattern, because its `fitted` field was already narrowed to concrete `FittedRidge` in 16.1-05 — see Deviations below.
- ElasticNet/RLS/BLS (the actual remaining `Box<dyn FittedRegressor>` holders) each get a captured `model_info: Option<ModelInfo>` field, set at the single `fit` site immediately before boxing.
- Extended `test_to_dict_values_are_json_like`'s allowed-type check to accept the `model_info` dict, since `model_info` is by design part of every fitted model's `to_dict()`.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Stale plan assumption] Ridge does not need boxed-capture; it already stores a concrete `FittedRidge`**
- **Found during:** Task 2 (reading `src/pymodels/py_ridge.rs`'s `fitted:` field type per the task's `<read_first>` instruction)
- **Issue:** The plan's context and acceptance criteria (`grep -c "model_info = Some(" src/pymodels/py_ridge.rs >= 2`) assumed Ridge still stored `Box<dyn FittedRegressor + Send + Sync>` alongside ElasticNet/RLS/BLS. In fact 16.1-05 had already narrowed `PyRidge.fitted` to a concrete `FittedRidge` (to support `variance_factor()`/`leverage_new()`, which are inherent, not trait methods). `HasModelInfo` is directly callable on the concrete type, so the boxed-capture machinery (extra field, capture at both `fit` and `fit_from_accumulator`) is unnecessary and would just be dead, parallel state.
- **Fix:** Gave Ridge the same direct `fitted.model_info()` getter as OLS (no new field). The plan's own behavioral requirement — correct, refit-safe `model_info` reporting — is still met; it's just met more simply than the stale plan text anticipated.
- **Files modified:** `src/pymodels/py_ridge.rs`
- **Verification:** `tests/test_model_info.py::test_model_info_matches_upstream[ridge]` passes; full suite green.
- **Committed in:** `2bfbd37` (Task 2 commit)

## Issues Encountered
- `tests/test_ergonomics.py::test_to_dict_values_are_json_like` failed once `model_info` (a dict) appeared in OLS's `to_dict()` output, since the test's allowed-type tuple didn't include `dict`. Extended the test to accept the `model_info` dict shape specifically (asserting its exact key set), rather than loosening the check generally — resolved before the Task 1 commit.
- `Isotonic().fit(...)` needed a flattened 1D `x` (it takes `PyReadonlyArray1`, unlike every other regressor in the table which takes 2D `x`) — caught by the first test run, fixed by slicing `x[:, 0]` in the test factory.
