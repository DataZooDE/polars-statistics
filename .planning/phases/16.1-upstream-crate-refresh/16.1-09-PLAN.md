<objective>
Lock the anofox-statistics 0.4.5 / 0.4.6 behaviour changes that the retarget to 0.4.6 brings in
(CONTEXT "Retarget to latest"): Hodges-Lehmann estimates and intervals now follow R's
`wilcox.test(conf.int = TRUE)` algorithm, exact null distributions no longer overflow and are only
used for small samples, `mcnemar_exact` no longer returns NaN for large discordant counts, and the
O(n^2)-memory paths are gone.

Purpose: UPST-02 for the 0.4.5 / 0.4.6 delta. Neither release adds public API (planning diffed every
`pub` item), so this plan is test-only.

Where the wrappers expose these fields (checked at planning time):
- `MannWhitneyU` / `WilcoxonSignedRank` PyModel classes expose `estimate` (float or None) and
  `conf_int` (ndarray [lower, upper] or None) → R-reference tests here.
- `ps.mann_whitney_u` / `ps.wilcoxon_signed_rank` expressions accept `conf_level` / `mu` but return
  only `{statistic, p_value}` — the estimate/CI are not surfaced at the expression layer. This is a
  pre-existing gap, not part of the upstream delta; it is locked by a schema test here and documented
  by Plans 06-08 (no schema change in 16.1).
- `ps.tost_wilcoxon_*` expose Hodges-Lehmann estimate / interval; upstream states their values are
  unchanged (order statistics now selected in O(n) memory) and that alpha > 0.5 no longer panics.
- `ps.mcnemar_exact` exposes the p-value → R-reference tests here.
- No existing test asserts the old order-statistic CI values (tests/test_test_models.py only checks
  types); Task 2 re-confirms this in an audit.
Output: one fixture CSV and one test file.
</objective>
