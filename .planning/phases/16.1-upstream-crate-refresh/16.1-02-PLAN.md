<objective>
Expose the anofox-statistics 0.4.3 effect sizes (Cohen's d family, rank-biserial family) and the
categorical additions (`conf_level` for binomial / proportion / Fisher tests, conditional
Fisher's exact test) as Polars expressions that follow the existing `#[polars_expr]` +
struct-output pattern.

Purpose: Implements these COVERAGE.md rows of UPST-03: cohens_d, cohens_d_one_sample,
rank_biserial, matched_pairs_rank_biserial, rank_biserial_from_u, binom_test_with_conf_level,
prop_test_one_with_conf_level, prop_test_two_with_conf_level, fisher_exact_with_conf_level,
fisher_exact_conditional.
Output: six new `pl_*` plugin functions with public `*_fit` Rust variants, four extended
categorical builders, typed Python builders exported from `polars_statistics`, tests.

Design decisions (Claude's discretion, project constraint "output-struct schemas"):
- Every effect size returns a single-field struct `effect_size{estimate: Float64}`, mirroring the
  existing single-field `dispersion_output_dtype` precedent.
- `fisher_exact` keeps `statistic` (sample odds ratio) and `p_value` and APPENDS `ci_lower`,
  `ci_upper` — the only way `conf_level` can be observable. Additive at the end; rated `costly`
  (published struct schema widens) per REVERSIBILITY_GATES, not `one-way`.
- The new trailing categorical scalar inputs are read tolerantly (`inputs.get(N)`, default 0.95)
  so existing downstream Rust rlib calls with the old arity keep working; the rlib smoke tests for
  every new/changed stats `*_fit` are added in Plan 04 (tests/rust_api.rs is owned by Plans 03/04
  to avoid a same-wave file overlap).
</objective>
