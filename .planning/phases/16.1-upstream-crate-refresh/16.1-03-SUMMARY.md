# Phase 16.1 Plan 03: GLM-Family Options — NegBin estimate_dispersion, RLS initial_p_diagonal, GLMM Wald Inference Summary

**Exposed three anofox-regression 0.5.14/0.5.15 options end-to-end — NegBin `estimate_dispersion` (R-validated Pearson-dispersion SEs), RLS `initial_p_diagonal` (P0 = delta*I prior), and GLMM Wald inference (`z_values`/`p_values`/`conf_int`, lme4-validated) — all additive, with every pre-existing public Rust `*_fit` contract untouched.**

## Accomplishments

- **NegBin `estimate_dispersion`** (Task 1, tracer): added the PyModel ctor kwarg + `dispersion` getter (`FittedNegativeBinomial::dispersion`); added `NegativeBinomialKwargs`/`NegativeBinomialPredictKwargs` (serde, named, additive) and `negative_binomial_fit_with`/`_summary_fit_with`/`_predict_fit_with`, with the existing `negative_binomial_fit`/`_summary_fit`/`_predict_fit` reduced to one-line delegations at the old default; wired `estimate_dispersion: bool = False` through `ps.negative_binomial`, `negative_binomial_summary`, `negative_binomial_predict`, `negative_binomial_formula`. Validated against MASS 7.3.65 (`anofox-regression` `issue49_negbin_se.rs`): default dispersion 1.0 / SEs `[2.953927095121e-01, 3.114970571954e-01]`; `estimate_dispersion=True` dispersion `0.8951608253323096` / SEs `[0.2794797246792255, 0.2947165213629392]`; coefficients unaffected.
- **RLS `initial_p_diagonal`** (Task 2): added the PyModel ctor kwarg + `initial_p_diagonal_value` getter; added `RlsKwargs`/`RlsPredictKwargs` (serde default `1e6`, matching `RlsRegressorBuilder`'s own default) and `rls_fit_with`/`_summary_fit_with`/`_predict_fit_with`, with the existing `rls_fit`/`_summary_fit`/`_predict_fit` reduced to delegations; wired `initial_p_diagonal: float = 1e6` through `ps.rls`, `rls_summary`, `rls_predict`, `rls_formula`. Proved default == explicit `1e6`, a tight prior (`1e-3`) measurably shifts coefficients/summary estimates/predictions on `y = 1 + 2x` (exact linear data), and an invalid delta (`-1.0`, `nan`) raises `ValueError` on the PyModel's `.fit()` and yields an all-NaN struct (never a panic) on the expression path — matching upstream's own `fit()`-time validation in `RlsRegressor::fit`.
- **GLMM Wald inference** (Task 3): added `GLMM.z_values`/`GLMM.p_values` getters and `GLMM.conf_int(level=0.95)` wrapping `FittedGlmm::z_values()`/`p_values()`/`conf_int()`; added the `(Bound<PyArray1<f64>>, Bound<PyArray1<f64>>)` → `tuple[numpy.ndarray, numpy.ndarray]` mapping to `scripts/gen_stubs.py`'s `RUST_TO_PY`. Validated against lme4 2.0.1 on scenario LMM_A (80 rows, 8 groups; `anofox-regression` `glmm_validation.rs` fixture + `issue51_glmm_inference.rs` references, copied verbatim): `z = [4.451695054970, 9.554977878286]`, `p = [8.519509552922e-06, 1.236103260560e-21]`, `conf_int(0.95)`/`conf_int(0.90)` bounds, plus internal-consistency identities (`z == fixed_effects/std_errors`, CI midpoint `== fixed_effects`, CI half-width `== 1.959963984540054 * std_errors`) and all-NaN bounds for five invalid `level` values (`0.0, 1.0, -0.5, 1.5, nan`).
- Regenerated `.pyi` stub after each task; stub-drift guard (`gen_stubs.py` + `git diff --exit-code`) clean after commit. ## Decisions Made

- Reviewed the stalled prior executor's uncommitted Task 1 diff against the plan line by line before touching anything; it matched action items 1-4 exactly (NegBin PyModel, Rust kwargs/`_with` fns, Python builders, `rust_api.rs` smoke tests), so it was kept as-is and only the missing pieces (test file, build, verify, commit) were completed.
- Since Tasks 1 and 2 both edit `src/expressions/regression.rs`, `python/polars_statistics/exprs/regression.py`, `tests/rust_api.rs`, and `tests/test_negbin_rls_options.py` in distinct functions, each task's edits to those shared files were temporarily set aside (exact-text `Edit` round-trips restoring the prior committed state, never `git stash`/`reset`) so Task 1's commit — and its full rebuild+verify cycle — reflects only NegBin code, and Task 2's commit only adds RLS code on top. This required three separate `maturin develop --release` rebuilds (one per task) instead of one, to keep each task's regenerated `.pyi` stub diff scoped to that task's new members.
- `negative_binomial_predict` has no `theta` kwarg in the existing builder (theta is always estimated for the predict path) — the plan's behavior bullet for the predict interval-width test implicitly assumed one; discovered via `TypeError` on first test run and corrected by dropping `theta=THETA` from that call.
- `RLS.initial_p_diagonal_value` is a `#[getter]` (mirrors the existing `forgetting_factor_value` precedent) and is accessed as a property (`model.initial_p_diagonal_value`), not called as a method — the plan's own prose ("add `fn initial_p_diagonal_value(&self) -> f64` next to `forgetting_factor_value`") is accurate about the Rust side but the first test draft called it with `()`, caught by the Task 2 pytest run and fixed.
- `GLMM.conf_int`'s clippy `type_complexity` lint (triggered by the tuple of two `Bound<'py, PyArray1<f64>>>`) is suppressed with `#[allow(clippy::type_complexity)]` rather than a type alias, so the return type stays on one line for `scripts/gen_stubs.py`'s literal-string `RUST_TO_PY` lookup (a type alias would make the signature resolve to the alias name instead of the mapped tuple string).
- `np.testing.assert_allclose(actual, desired, atol=<array>)` crashes with `TypeError: unsupported format string passed to numpy.ndarray.__format__` on this numpy version (2.3.5) even when the comparison itself would pass — it builds the `f'...atol={atol:g}'` header unconditionally before running the comparison. The two GLMM z/p-value reference tests were written as manual per-element loops instead of a single `assert_allclose` call with an array `atol`.
